# 手册维护指南

本文件说明本手册的维护流程、版本口径与写作红线。手册面向中文读者，并为后续的检索工具提供结构化索引（`index.json`）。

> AI/自动化维护必须先读 [`AGENTS.md`](AGENTS.md)，再按本文件与其中的「文档维护与 AI 生成规则」执行。

## 版本号来源

手册版本必须与服务版本一致，来源按优先级如下：

1. 仓库的 git tag（形如 `v12.1.6`）。
2. `src/Midjourney.API` 程序集版本（项目文件中的版本信息）。
3. 两者不一致时，以当前 checkout 的实际程序集版本为准，并在维护记录中注明差异。

当前手册对应版本：**v12.1.6**。

## 升级步骤清单

版本升级或内容批量更新时，按以下顺序执行：

1. 更新子模块到目标提交，确认工作区处于预期版本。
2. 确认版本号：核对 git tag 与 `src/Midjourney.API` 程序集版本。
3. 重新生成发布归档与提交归档。
4. 重新采集截图（线上公益站，见「截图规范」），确保界面与当前版本一致。
5. 更新手册中的版本号、受影响章节与 `index.json` 的 `version` / `lastUpdated` 字段。
6. 运行文档校验，修复断链、缺失索引与占位符问题。
7. 复核红线：确认没有出现真实凭据与内部实现细节。
8. 提交变更。

## 截图规范

- 截图统一从线上公益站 `https://ai.trueai.org` 采集，不启动本地演示实例，也不使用本地合成数据；Swagger 截图可用同版本本地实例采集（见下条）。
- 视口固定为 **1366×768**、`deviceScaleFactor=1`、`mobile=false`，只截当前视口；不拼接整页，输出 PNG 的宽高必须精确为 1366×768（脚本会用 IHDR 校验，不符即报错）。
- 敏感内容必须在截图前脱敏：账号「服务器ID」「频道ID」与任务「实例ID」按「前 6 位 + `...` + 后 4 位」部分脱敏；账号备注、任务描述/提示词列替换为 `***`；表格缩略图替换为灰色占位块；用户邮箱/手机/IP 列替换为 `***`；违规词条的名称与描述替换为 `***`（保留行数与列宽）。
- 欢迎页隐藏「系统信息」「程序信息」「服务器信息」与「今日绘图 TOP 10」；绘画测试隐藏「最近任务」面板；日志页把日志文本替换为占位文案。
- 设置页截图不得出现任何敏感配置区域，也不得出现真实连接串、密钥、Token 或账号信息，只保留「其他设置」分组。
- 凭据、账号、密钥与连接串统一使用占位符；公开演示地址（验证器、MinIO 示例、图片示例）按实际地址展示。
- Swagger 截图取自本地同版本实例（本地源码已修复 Swagger 文档生成问题）：在仓库外的临时目录启动启用演示模式与 Swagger 的实例，确认 `/swagger/v1/swagger.json` 返回 200 后采集，用完删除临时目录。线上演示站尚未部署最新修复时仍可能返回 500，部署更新后恢复；脚本检测到线上报错页会跳过并保留现有文件。
- 红线：任何真实凭据、手机号、邮箱、连接串等敏感内容都不允许出现在截图或文档中；公开演示地址按实际地址展示，不要改回占位符。

## 提交边界

- 只在 `midjourney-proxy` 子模块内提交手册相关改动，不混入其他仓库。
- 不提交 `.screenshots` 运行目录、数据库文件、日志、`bin/`、`obj/` 等生成物。
- 提交前确认 `index.json` 为合法 JSON，且每个条目指向实际存在的文件。

## 新增章节

1. 在 `docs/manual/` 下按 `NN-name.md` 命名新增文件。
2. 使用一级标题，并保留「适用版本 / 适用读者 / 前置条件」三行元信息。
3. 在 `index.md` 的章节导航表格与 `en/README.md` 的索引表格中补充对应条目。
4. 在 `index.json` 中追加条目，保持 `order` 连续稳定。
