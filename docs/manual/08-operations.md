# 08 运维

- **适用版本**：v12.1.6
- **适用读者**：承担日常维护、容量规划与安全加固的运维人员
- **前置条件**：已掌握实例的部署方式与配置来源，具备日志与数据库操作权限

本章面向长期运行：说明如何查看日志与健康状态、如何备份恢复与迁移数据、如何调优性能与设置告警，以及升级回滚与安全加固的常规做法。具体故障现象与定位步骤见第九章。
## 日志
### 日志目录与滚动
服务使用 Serilog 统一输出，同时写入控制台和文件，默认目录为运行目录下的 `logs/`（容器内为 `/app/logs`、`/app/data`）。容器部署时 `/app/logs` 通常挂载到宿主机，启动、数据库切换、Redis 检测、账号初始化、任务与回调等关键动作都会写入日志。

| 文件 | 内容 | 滚动与保留 |
| --- | --- | --- |
| `logs/log.txt` | 达到当前级别的全部日志 | 按天滚动，单文件 10MB，保留 31 个文件 |
| `logs/error.txt` | 仅 Error 及以上级别 | 按天滚动，单文件 10MB，保留 31 个文件 |
| 容器标准输出 | 与控制台一致 | 由 Docker 日志驱动管理，需单独配置轮转 |

### 日志级别调整
日志级别来自系统配置项 `LogEventLevel`，默认 `Information`。管理员保存设置后立即更新全局日志开关，不需要重启进程。

- `Default`、`System`、`Microsoft` 默认压到 `Warning`；把业务日志调到 `Debug` 也不会让框架日志全部输出。
- 临时排查可短时调为 `Debug`，定位后调回 `Information`，否则日志量与磁盘占用会明显上升。
- FreeSql 慢查询超过 500ms 记 Warning，超过 2000ms 同样记 Warning，可用于判断数据库是否拖慢任务。
### 关键字与检索建议

| 场景 | 建议检索关键字 | 说明 |
| --- | --- | --- |
| 启动与关闭 | `应用程序正在启动`、`Current directory` | 确认进程完整启动、工作目录正确 |
| 数据库 | `数据库连接失败`、`数据库类型`、`切换为 SQLite` | 判断是否进入降级模式 |
| Redis | `Redis 连接成功`、`已自动禁用 Redis` | 判断队列、缓存与分布式锁是否可用 |
| 账号初始化 | `初始化失败`、`非工作/摸鱼时间`、`账号用量已经用完` | 禁用账号会同时写入禁用原因 |
| 任务与回调 | `任务执行结束`、`任务提交超时`、`队列已满`、`Notify task change fail` | 覆盖执行、容量与回调问题 |

```bash
grep -n "数据库连接失败\|Redis 连接失败\|初始化失败\|Notify task change fail" logs/log.txt
```

日志可能包含账号渠道 ID、任务 ID、客户端 IP 等运行信息。对外提供日志前必须脱敏，不要把包含 Token、Cookie、连接串或回调密钥的原始行贴到公开渠道。
## 健康检查
### 检查端点

| 端点 | 实现 | 返回 | 鉴权 |
| --- | --- | --- | --- |
| `GET /health` | ASP.NET Core `MapHealthChecks` | 纯文本 `Healthy`，HTTP 200 | 跳过 |
| `GET /Health` | `HealthController` | JSON：`Status`、`Timestamp`、`MachineName`、`ProcessId` | 跳过 |

```bash
curl -fsS http://127.0.0.1:8080/health
curl -fsS http://127.0.0.1:8080/Health
```

- `/health` 当前没有注册数据库、Redis 等自定义检查项，只代表进程可响应请求。
- `/Health` 返回进程标识，用于确认请求打到了哪个实例；字段名可能按实际序列化配置输出为 camelCase。
- 两个端点都不校验登录态，应在网关层限制访问来源，避免主机名与进程号暴露到公网。
### 依赖组件检查

| 组件 | 检查方式 | 健康表现 | 异常表现 |
| --- | --- | --- | --- |
| 数据库 | 日志 `数据库类型`、`SELECT 1`、后台验证连接 | 显示目标库且无重试 | 10s/60s/360s 重试后切换 SQLite |
| Redis | `redis-cli ping`、启动日志 | 返回 `PONG`，日志显示已启用 | Ping 失败并自动禁用 |
| 账号池 | 后台账号列表、首页概览 | 在线数与额度正常 | 大量账号禁用并带原因 |
| 队列 | 首页并发/队列概览、日志 | 有消费、无持续堆积 | 持续「队列已满」或任务不开始 |
| 存储与回调 | 抽取结果 URL、对端接收记录 | 200 且有推送成功日志 | 404/403，或出现 `Notify task change fail` |

管理员接口 `POST /mj/admin/validate-database-connection` 可验证数据库；保存系统设置时也会先验证 Redis 与数据库，失败会拒绝写入，不会把不可用配置写回。
### 接入外部监控
- 外部探针每 30–60 秒请求 `/health`，连续 3 次失败或超时告警；它只能发现进程级故障。
- 容器层采集 CPU、内存、磁盘、网络与重启次数；日志目录与附件目录单独监控水位。
- `/mj/home` 提供今日/昨日/总绘图量、成功失败统计、实时并发与队列概览；统计缓存 10 分钟、实时概览缓存 10 秒，适合看趋势而非秒级告警。
- 启用 Consul 时默认以 `/health` 做健康检查，间隔 10 秒、超时 5 秒、严重失联 1 分钟后注销；当前没有内置 Prometheus 指标端点。
## 备份与恢复
### 需要备份的数据范围

| 数据 | 位置 | 说明 |
| --- | --- | --- |
| 系统配置 | `data/mj.json`（容器 `/app/data/mj.json`） | 未启用 Consul 时是唯一配置来源 |
| SQLite | `data/mj_sqlite.db` | 使用 SQLite 时必须备份，路径固定 |
| 服务型数据库 | MySQL/PostgreSQL/SQLServer | 使用数据库原生备份，不要只备份容器 |
| 本地附件 | `wwwroot/attachments`、`wwwroot/ephemeral-attachments` | 本地存储时必须随数据目录一起备份；`logs/` 按审计要求可选备份 |
| 对象存储 | OSS/COS/R2/S3 桶 | 依赖桶版本控制或跨区域复制 |
| Consul KV | `{ServiceName}/setting` | 启用 Consul 时与本地配置同等重要 |
### 备份频率与保留策略
1. 数据库至少每日一次全量备份，重大变更前额外做即时备份。
2. 配置文件纳入版本化管理，至少每日备份；启用 Consul 时同步导出 KV 或 Consul 快照。
3. 本地附件按增量备份，对象存储开启版本控制；保留周期与业务留存要求一致。
4. 建议保留 7 个日备份、4 个周备份并定期演练恢复；备份与密钥分离存放，介质加密。

```bash
# 停写后打包配置、SQLite 与本地附件（路径按实际挂载调整）
docker stop mjopen
tar -czf mjopen-backup-{date}.tar.gz /root/mjopen/data /root/mjopen/attachments /root/mjopen/ephemeral-attachments
docker start mjopen

# SQLite 在线备份与 MySQL 逻辑备份（连接参数使用占位符）
sqlite3 /app/data/mj_sqlite.db ".backup '/backup/mj_sqlite.db'"
mysqldump -h {host} -u {user} -p {database} > mjopen-{date}.sql
```
### 恢复流程与校验
1. 停止应用，避免恢复过程中仍有写入。
2. 恢复数据库到原类型、原连接串；更换数据库类型时先初始化结构，再按「数据迁移」处理。
3. 恢复 `data/mj.json` 与附件目录，保持相对路径不变，确认容器挂载与权限。
4. 启动后确认日志中的数据库类型、Redis 状态与账号初始化结果。
5. 核对账号数、任务数、今日统计、配置版本，抽查历史任务与图片 URL；提交测试任务并验证回调，随后修改可能暴露过的凭据。

启用 Consul 时启动优先使用 Consul KV，本地 `data/mj.json` 只作为应急启动配置且不会自动写回。恢复时必须同时确认远程 KV 的版本与内容，避免本地恢复被远程配置覆盖。
## 数据迁移
### 数据库类型切换
支持 SQLite、MySQL、PostgreSQL、SQLServer；历史枚举值 1/2 按 SQLite 处理。SQLite 连接串固定为 `Data Source=data/mj_sqlite.db`，不能改到其他路径。

1. 备份当前数据库与 `data/mj.json`。
2. 在目标库创建空库与账号，授予建表、索引、读写权限；PostgreSQL 按需启用扩展。
3. 在管理后台填写目标类型与连接串，先执行「验证数据库连接」。
4. 保存设置。保存还会校验数据库、Redis、版本与内部校验项；具体错误以界面提示为准。
5. 重启应用。启动时自动建表并补齐缺失字段与索引，结构同步超时上限 600 秒；确认无重试、无降级后再放量。

内置迁移适用于一次性搬运：开启 `IsAutoMigrate`，配置 `MigrateDatabaseType` 与 `MigrateDatabaseConnectionString`，启动时把源库中目标库不存在的账号、用户、违规词和任务按 ID 补入当前库。

- 只补缺失记录，不覆盖同 ID 数据，不能当作持续同步；任务迁移在后台异步执行，期间不要反复重启。
- 源库与目标库不能相同，保存时会直接拒绝；迁移完成后关闭 `IsAutoMigrate`。
### 附件与静态资源迁移
- 本地存储写入 `wwwroot/attachments` 与 `wwwroot/ephemeral-attachments`，迁移时保持相对目录结构，不要只复制部分日期。
- 切换对象存储时先迁移历史文件并保持 Key 不变，再修改 `ImageStorageType` 与桶配置；历史任务中的旧 URL 不会自动改写。
- 自定义 CDN 只改变访问域名，不改变存储 Key；需要兼容旧链接时保留旧域名解析与回源，或按业务规则批量改写数据库 URL，改写前必须备份。
### 迁移后的验证

| 验证项 | 方法 | 通过标准 |
| --- | --- | --- |
| 数据结构 | 日志、表与索引 | 无同步错误，关键索引存在 |
| 记录数量 | 账号、用户、任务计数 | 与迁移前一致或在预期差异内 |
| 历史任务 | 随机抽取任务详情 | 字段完整，图片/视频 URL 可访问 |
| 新任务 | 提交测试任务 | 正常入队、执行、完成 |
| 配置与回调 | 设置页版本号、对端接收日志 | Revision 未冲突，能收到终态回调 |
## 性能调优
### 并发与队列参数

| 参数 | 默认/范围 | 作用与影响 |
| --- | --- | --- |
| `CONCURRENT` | 默认 `min(1280, CPU×64)`；`0` 与 `-1` 均按 1280 处理，不能用于停止任务 | 单节点全局任务并行上限 |
| 执行器容量 | 并发的 2 倍，32–1280 | 未消费任务的缓冲上限，满后产生背压 |
| 执行器最大并发 | 并发的 1.2 倍，32–1280 | 实际同时消费的任务数 |
| 账号 `CoreSize` | 默认 3；Excel 导入限制 ≤12 | 单账号同时执行数 |
| 账号 `QueueSize` | 默认 10；Excel 导入限制 1–100 | 快速/默认队列等待上限 |
| `RelaxQueueSize` | 默认 10 | 慢速队列等待上限，主要影响悠船慢速 |
| `Interval` / `AfterInterval*` | 默认 1.2 秒 | 任务提交间隔，过小更易触发风控 |
| `TimeoutMinutes` / `NotifyPoolSize` | 5 分钟 / 10（内部上限 64） | 执行超时与回调并发 |

Excel 导入会限制 CoreSize ≤12、QueueSize 1–100；账号表单仅校验 ≥1，服务端没有同样上限。

1. 先增加账号、分散渠道，再考虑提高单账号并发；并发过高更容易触发下游限流。
2. 队列持续满时先判断是任务突增、账号掉线还是消费被慢任务占满，不要直接调大 `QueueSize` 掩盖问题。
3. 放大任务使用独立队列且允许溢出，不受普通队列上限约束；账号并发与队列的部分参数要等重连或下次启动才完全生效。
### 数据库与缓存调优
- 任务表最大，已按用户、渠道、状态、提交时间、模式、动作建立索引；排障时避免无条件全表扫描与超大 `IN` 查询。
- 默认最多保留 50 万条任务（`MaxCount`），超出后每次删除最早的 1000 条，循环到阈值附近；下调会丢失更早记录。
- 出现大量慢查询时优先检查索引、连接池与磁盘 IO；MySQL 关注缓冲池与 redo，PostgreSQL 关注 `shared_buffers` 与连接数。
- SQLite 适合中小规模，写入并发高时切换到服务型数据库。
- Redis 与应用同区域部署，关注内存、命中率、持久化与网络延迟；多节点必须连接同一 Redis 与同一数据库，否则队列、缓存和配置会分裂。
### 静态资源与 CDN

| 存储方式 | 适用场景 | 注意事项 |
| --- | --- | --- |
| `NONE` | 只转发、不落地 | 返回上游链接，可能过期或受防盗链影响 |
| `LOCAL` | 单机或共享卷 | 需要持久化挂载，预留磁盘 IO 与容量 |
| `OSS` / `COS` / `R2` / `S3` | 多节点、大流量 | 配置桶、密钥、区域与访问域名，注意跨域与私有读 |

- 自定义 CDN 只改访问域名，不改存储 Key；本地附件流量大时应前置 Nginx/CDN，避免应用承担全部图片带宽。
- 对象存储可配置图片、缩略图与视频截帧样式；切换存储或 CDN 后必须同时验证新任务与历史任务链接。
## 告警
### 告警指标
内置预警在每次例行检查时评估阈值，支持邮件与 Webhook：

| 指标 | 含义 | 触发方向 |
| --- | --- | --- |
| `FastRemaining` | 今日快速剩余额度 | 小于等于阈值 |
| `RelaxedRemaining` | 今日慢速剩余额度 | 小于等于阈值 |
| `WarningCount` / `ErrorCount` | 最近一小时 Warning / Error 数 | 大于等于阈值 |
| `AvailableAccountCount` | 当前启用账号数 | 小于等于阈值 |

外部监控应补充：`/health` 失败、任务失败率、队列堆积、回调失败率、数据库/Redis 状态、磁盘水位、容器重启次数。
### 通知渠道配置
- 邮件：配置 SMTP 主机、端口、SSL、发件人与收件人；邮件也是 Cloudflare 人工验证链接的兜底通知渠道。
- Webhook：配置 `AlertNotify.NotifyHook`，服务 POST JSON，超时 10 秒。
- 频率限制：每小时最多 10 次、每天最多 100 次；冷却默认 30 分钟，可配置 1–1440 分钟；配置后主动触发一次测试。
### 告警抑制与分级
1. P1：服务不可用、数据库/Redis 长时间不可用、全部账号掉线，立即处理并即时通讯触达。
2. P2：部分账号禁用、失败率上升、队列持续堆积、回调大面积失败，工作时间内处理。
3. P3：额度不足、磁盘接近阈值、单条回调失败，按计划处理。
4. 同一指标在冷却时间内只通知一次；维护窗口暂停非关键告警；告警内容写清实例、指标、当前值、阈值、日志位置与建议动作。
## 升级与回滚
### 升级前准备
1. 阅读发布说明，确认配置项、数据库结构与接口是否有破坏性变更。
2. 备份数据库、`data/mj.json`、本地附件与 Consul KV。
3. 确认容器挂载、端口、时区、运行用户与镜像标签；升级脚本会删除并重建容器，数据依赖宿主机挂载保留。
4. 确认所有节点版本一致；离线环境关闭自动更新检查，选择低峰窗口并准备上一版本镜像。
### 升级步骤
```bash
# Docker 脚本会拉取镜像、删除旧容器并按原挂载启动新容器
bash scripts/docker-upgrade.sh
```

1. 拉取目标镜像并记录镜像摘要；删除旧容器，保留 `data`、`logs`、`attachments`、`ephemeral-attachments`。
2. 用相同网络、端口、挂载与环境变量启动新容器。
3. 查看启动日志：数据库类型、Redis 状态、账号初始化、表结构同步是否有错误。
4. 验证 `/health`、后台登录、账号在线数、任务列表、测试任务与回调。

在线升级：检查更新 → 下载升级包（状态变为「下载完成，等待重启」）→ 触发重启。容器环境通过退出进程交给重启策略拉起，非容器环境由升级脚本替换文件后重启；升级包与解压目录位于应用目录下的 `Upgrade`，需要写权限与足够磁盘。升级后核对版本号、配置 Revision 与数据库结构。
### 回滚条件与操作
出现以下情况应回滚：新版本无法启动或持续崩溃；大面积账号无法上线、任务无法提交或全部超时；数据库结构导致旧代码无法读写；配置行为严重不符且短时间无法定位。

1. 停止新版本，保留现场日志与容器信息。
2. 切回上一版本镜像或上一份发布目录，不要只回退单个 DLL。
3. 新版本已修改数据库结构时，恢复升级前数据库备份；仅回退程序可能因结构不兼容而失败。
4. 恢复升级前的 `data/mj.json`；启用 Consul 时同步恢复 KV，启动后验证账号、任务、配置与回调并记录回滚原因。
## 安全加固
### 凭据与密钥管理
- 管理员 Token 必须通过部署配置注入强令牌，禁止在未注入状态下上线。
- 仓库示例 compose 含演示弱口令，部署前必须全部替换；文档示例不写入真实凭据。
- Redis 密码、数据库口令、对象存储密钥、2FA 密钥、回调密钥统一放入密钥管理或环境变量，不写入仓库、镜像与文档。
- 不同环境使用不同凭据；人员变动或疑似泄露后立即轮换；日志、截图、工单与告警内容不得出现 Token、Cookie、连接串或完整账号信息。
### 网络与访问控制
- 对外只暴露反向代理的 443/80，应用端口仅在内网或容器网络可达；全站启用 HTTPS。
- 反向代理正确传递真实客户端 IP，否则基于 IP 的限流与白名单会失真。
- 管理后台限制来源 IP、VPN 或独立域名，不要把 `/mj/admin` 暴露给公网匿名访问。
- 当前 CORS 允许任意来源并携带凭据，生产环境应在网关层限制 `Origin`，不要依赖应用内 CORS 做安全边界。
- `/health` 与 `/Health` 不鉴权；普通限流命中返回 429，黑名单限流命中返回 403，匿名接口、管理员与白名单用户不参与限流。
### 后台暴露面收敛
```text
isDemoMode = false
enableRegister = false
enableGuest = false
enableSwagger = false
enableUpdateCheck = false        # 离线环境按需关闭
ipRateLimiting.enable = true
ipBlackRateLimiting.enable = true
```

- 演示模式会跳过全部鉴权并默认开放 Swagger，只能用于公开演示，绝不能用于生产。
- 首次启动在无配置文件时默认开启注册与访客，必须显式关闭，并确认注册依赖的邮件服务没有被误配置。
- 关闭 Swagger，或仅在维护窗口临时开启并限制来源；关闭不需要的绘图后端与功能开关，删除测试账号与长期不用的调用方 Token。
### 日志脱敏要求
- 日志保留 31 天，属于敏感运行数据；目录权限仅授予运维账号。
- 不记录明文 Token、Cookie、密码、2FA 密钥、连接串、对象存储密钥与回调签名密钥。
- 账号日志优先记录渠道 ID、账号 ID 或脱敏账号；对外提供日志前删除主机名、内网 IP、客户端 IP、回调地址与密钥字段；备份文件同样加密。
